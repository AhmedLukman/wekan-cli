# Wekan API-to-CLI coverage

This inventory maps the audited native REST contract for **Wekan v12.57** to
production CLI parser and dispatch paths. Generate the corrected contract from
[the untouched upstream snapshot](../spec/wekan.yml) and
[the verified overlay](../spec/wekan.overlay.yml), following
[API reference generation](../CONTRIBUTING.md#api-changes).

**Coverage:** 167 of 167 in-scope operations implemented (100%); 0 remaining; 1 intentionally excluded.

The corrected contract contains 168 audited operations. The Amazon SES/SNS
endpoint is intentionally excluded from typed CLI support and remains listed
in the table for a complete audit trail.

The total counts HTTP method/path operations. Dynamic source and export-format
values select implementations within those operations. All 49 import sources,
40 external export formats, 21 chart types, and the native board/card formats
are listed explicitly in the corresponding command syntax. Repeated options
end in `...`; conflicts and required update groups follow each syntax.
Every command lists its optional global flags as well as its resource options.

The 57 optional Trello/Jira/GitHub/Gitea compatibility operations are excluded
from typed support. Browser and DDP protocols, metrics, direct file serving,
identity-provider callbacks, and framework-generated HEAD/OPTIONS are excluded.
The native `/import-trello` endpoint and explicitly registered authentication
preflights remain included. The [raw API command](api.md) preserves full native
payloads and responses for operations outside this typed contract.

Successful typed responses reject unknown fields at every object depth. Optional
stored settings, metadata and native export records are mapped explicitly.
User-record responses map optional numeric `profile.notifications[].showAt` to
`profile.notifications[].show_at` in user detail output; `auth status` validates
the same record before projecting authentication metadata.
This includes all 114 card settings, label milestone/shared IDs, group/custom-role
memberships and checklist item assignee/linked-card references.
Attachment deletion retains the file and can be reversed through restoration.
A successful user creation returns its ID; user deletion reports `deleted`.
Provider email hooks use their native signature/secret gates and preserve body
bytes.
Rule enablement updates accept only JSON booleans; explicit null is rejected
before HTTP. JSON upload bodies encode `fileData` as base64 text. Raw background
uploads default to `image/png`; their native partial failure is recorded as
W12-006 and is returned without retrying or changing transport. Native filename
normalization can asynchronously remove a raw upload after its response (W12-007).

Implementation coverage does not imply that an upstream defect is repaired.
[Compatibility notes](compatibility.md) and the maintained v12.57 defect report
record verified native failures; the CLI preserves those responses.
